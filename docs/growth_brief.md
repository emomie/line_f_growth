# タロチャ グロース戦略ブリーフ（健康診断 → プレモータム → 健全な成長）

作成: 2026-09-28 / satie
正本: https://claude.ai/code/artifact/e8d50e19-61d1-4152-8272-39f20042507e （編集はそちらで。このファイルはプロジェクト知識用の写し）

## 使い方

タロチャを「伸ばして大丈夫な体か」検査してから伸ばすためのブリーフ。順番は ①健康診断 → ②プレモータム → ③健全な成長の条件 → ④成長の打ち手。③の条件を満たすまで④は開かない。数字が揃っていなくても「何から測るべきか」の相談から入ってよい。

起動プロンプト:

```
このドキュメントは、タロチャ（LINEの都度課金タロット占いボット）の成長戦略ブリーフです。
目的は「伸ばす」前に「伸ばしても死なないか」を検査すること。
進め方は ①健康診断 → ②プレモータム → ③健全な成長の条件 → ④成長の打ち手。
①から始めてください。書いてある数字を判定基準に当てて青/黄/赤をつけ、
足りない数字は「取れない」と明示して、計測の整備を最初の一手にしてください。
③の条件を満たすまで④には進まないでください。
発散は歓迎、思考の飛躍も歓迎。ただし判定と打ち手の段階では忖度なしで。
PM職としてではなく、一個人の開発者として接してください。日本語でカジュアルに。
```

## ① 健康診断

ゴールは「売上の質が伸ばしていいものか」を判定すること。直近30日、可能なら3ヶ月の推移。閾値は仮置き（個人開発の都度課金サービスの経験則）。取れない数字は「取れない」と書く。

| 指標 | 何が分かるか | 青 | 黄 | 赤 | 記入 |
| --- | --- | --- | --- | --- | --- |
| 月次売上（3ヶ月の推移） | 伸びが実在するか | 3ヶ月連続で増 | 横ばい | 減少 | |
| 上位5%ユーザーの売上シェア | 少数への寄りかかり | 30%未満 | 30〜50% | 50%超 | |
| ユーザーあたり月間占い回数（中央値 / 最大値） | 依存の兆候 | 最大が中央値の10倍未満 | 10〜30倍 | 30倍超、または1日10回超の人がいる | |
| 依存的利用と見なすユーザーの人数と売上シェア | 倫理と事業の両方のリスク | シェア10%未満 | 10〜30% | 30%超 | |
| 1占いあたり粗利（単価 − LLM費 − LINE送信費） | 1回ごとに儲かっているか | 単価の50%超 | 20〜50% | 20%未満 | |
| 新規ユーザー / 既存ユーザーの売上比 | 穴の空いたバケツか | 既存が過半 | 半々 | 新規が7割超 | |
| 友だち追加数とブロック率（月次） | 入口の健全さ | 追加が増、ブロック率20%未満 | 横ばい | ブロック率30%超 | |
| 初回課金率（友だち追加 → 初回課金） | 無料から有料への壁 | 5%超 | 2〜5% | 2%未満 | |
| 2回目課金率（初回課金 → 翌月も課金） | リピートの実在 | 30%超 | 15〜30% | 15%未満 | |
| 現行モデルの提供終了日と代替モデルの質感テスト結果 | 「解決しない共感」の寿命 | 代替で質感OK確認済み | 終了日は把握、代替は未検証 | 終了まで6ヶ月以内で代替未検証 | |
| LINE以外のユーザー接点の有無 | プラットフォーム集中 | 接点あり、連絡可能 | 接点はあるが連絡手段なし | ゼロ | |
| 返金要求・家族からの問い合わせ件数（月次） | 課金確認なしのツケ | 0件 | 1〜2件 | 3件以上、または継続的 | |

Claudeに頼むこと:
- 数字を青/黄/赤に振り分け、赤と黄を一覧にする
- 「取れない」指標について、最短で取れる計測の一手を提案する
- 上位5%シェアと回数分布は、数字が無くても体感で仮置きする。ここが空だと②が始まらない
- ユーザーの生の声を、褒め・不満・依存の兆候の3つに仕分ける
- 最後に健康状態を10行以内で要約する

## ② プレモータム

ゴールは「1年後にタロチャが死んでいた」と仮定して死因を先に書き、①の数字で「支持 / 否定 / 判断不能」に振り分け、緊急度順に並べること。「強みに見えているもの」を特に疑う。

| 死因 | 出ているはずの兆候 | 見る数字 | 判定 | 緊急度 |
| --- | --- | --- | --- | --- |
| 売上が依存ユーザーで成り立っていた。グロース＝依存者を増やすことだった | 上位数%への売上集中、1日に何度も占う人、深夜の利用偏り | 上位5%シェア、回数分布、依存ユーザーのシェア | | |
| 旧GPT-4系の提供終了で「解決しない共感」の質感が消え、乗り換え後に離脱 | 代替モデルの応答が課題解決寄りになる | 提供終了日、質感テスト結果 | | |
| LINEの料金改定・ポリシー変更・アカウント停止で一夜にして売上ゼロ | 送信コスト上昇、占い・AIカテゴリへの警告 | LINE以外の接点比率、送信費の推移 | | |
| 課金確認なしの都度課金が消費者トラブル化（返金、家族からの苦情、通報） | 返金要求、「知らないうちに」系の問い合わせ | 問い合わせ件数、明細の有無 | | |
| プル型の天井：新規が止まった瞬間に売上が落ちた | 売上の伸びが新規流入と同期、2回目課金率が低い | 新規/既存の売上比、2回目課金率 | | |
| 無料のAI占い（ChatGPT直打ち含む）に単価を削られた | 「高い」系の声、高単価メニューからの離脱 | 競合3つの価格、メニュー別課金率 | | |
| 作者が飽きた、または本業と介護で運用が回らなくなった（一人開発の最大の死因） | リリース間隔が伸びる、問い合わせ返信が遅れる | 直近リリース日、週の運用時間 | | |
| 占いの「効果」表現や課金表示が景表法・特商法に引っかかった | 指摘・問い合わせ、同業への行政指導ニュース | LP・ボット内の表現の棚卸し | | |

飛躍した死因も歓迎。例:
- 依存対策の「カードが覚えている」機構が、逆に離れられなくする装置になっていた
- 一番課金している層と、作者が届けたい「自己発見の余白」を求める層が別人だった
- プッシュ型の姉妹プロダクトを作ったら、タロチャのユーザーが移って共食いした

Claudeに頼むこと:
- 自分では思いつかない系統の死因を3つ以上足す
- 各死因を①の数字と声で振り分け、緊急度（高＝3ヶ月以内に起こりうる）をつける
- 「判断不能」の死因について、判断できるようにする最小の調べ方を提案する
- 競合が同じ死因をどう避けているか3サービス分比べる（competitive-brief）
- 「こだわっているが死因とは無関係な点」を率直に指摘する

## ③ 健全な成長の条件

「伸ばしていい」を感覚ではなく条件で決める。②で「支持」になった死因は必ずここに入る。初期値は仮置き。

伸ばす前に満たす条件（全部満たすまで④は開かない）:
- [ ] 上位5%の売上シェアが30%未満、または依存対策（回数上限・クールダウン・「カードが覚えている」）が本番で動いている
- [ ] 代替モデルでの質感テストが完了し、乗り換え手順が書いてある
- [ ] 1占いあたり粗利が単価の50%超
- [ ] 2回目課金率が15%超
- [ ] 後から見て納得できる課金明細と、月間の上限がある
- [ ] LINE以外にユーザーへ連絡できる接点が1つある

伸ばしている最中に見張る指標（週次）: 回数分布の最大値と1日10回超のユーザー数 / ブロック率 / 1占いあたり粗利 / 返金・苦情の件数

止める条件（どれか1つで集客を止めて先に直す）: 1日10回超のユーザーが新規の1%超 / 返金・苦情が月3件以上 / ブロック率30%超 / 粗利が単価の20%割れ

Claudeに頼むこと: ①②の結果で条件を追加・削除・閾値修正する / 未達の条件ごとに最小の施策と時間を見積もる / 「厳しすぎて永遠に伸ばせない」という反論も忖度なしで述べる

## ④ 成長の打ち手

③を全部満たしてから開く。ゴールは「次の2週間でやる施策を1つ」と「その次の候補を3つ」。

Claudeに頼むこと:
- 一番弱かった段に打ち手を10個（うち3つは自分では思いつかない系統）
- 「効果の大きさ × 実装の軽さ」で評価、2週間で検証できるものを優先
- 各打ち手が②の死因を悪化させないかチェック（例: 月額パスは単価を上げるが依存を加速する）
- 上位1つの手順・時間・成功と判断する数字を書く
- 「やらないこと」を明記。最後に反論を1つ

打ち手の系統: 友だち追加（X発信、占い系コミュニティ、他LINEボットと相互紹介、読み物記事→LINE） / 初回→初回課金（無料分の線引き、初回体験の深さ） / 初回→2回目（カードが覚えている、月初の無料1枚、振り返り通知） / 単価（回数券、松竹梅。月額パスは依存とのトレードオフを先に見る） / プッシュ型姉妹プロダクトへのクロスセル（共食いしない設計が前提）

## 進め方

①で1回、②③で1回、④で1回に分ける。数字を追加できたら①をやり直す。

| ステップ | 使うスキル | 頻度 |
| --- | --- | --- |
| ① 健康診断 | metrics-review, synthesize-research | 月1回 |
| ② プレモータム | brainstorm, competitive-brief | 四半期に1回、または赤が出たとき |
| ③ 成長の条件 | mandalart-biz-check | ②のあと |
| ④ 打ち手 | roadmap-update | 2週間に1回 |
| 施策の実行 | Marketing プラグイン、SEOなら seo-audit | 施策ごと |

会話の回し方: 各ステップの最後に「決まったこと」を5行以内でログに追記 / ②で支持された死因は③の条件に追加 / 2週間後に結果の数字を持って戻る / ③の止める条件を踏んだら①に戻る / 3回まわしても動かなければ「誰向けか」を疑う
