## 集計の定義（9/28の数字を再現したもの）

- 占い到達 = 6/28以降に `user_tickets` の used がある人 = **109人**（テスト id 1,2 を除く）
- そのうち 課金6 / **A群57**（used 3回以上・未課金）/ **B群32**（used 1回・残り2回・未課金）/ その他14
- 占い回数 = `user_tickets` の used 件数。残り回数 = `user_statuses.count`。売上 = `payments` の `status='completed' AND amount>0`
- 登録時の無料3回と月初の無料1枚は、どちらも `system_grant` → `monthly_free` チケット。月初の1枚は**残り回数が0の人にだけ**配られる

- 占い到達者のうち1回で止まる率: Google期（6/1〜8/9）45%、Instagram期（9/7〜）53%（n=15）。差は言えない
- 32人中27人は**登録当日に1回だけ**占って戻っていない
- B群は無料2回を残しているので、月初の無料1枚が届かない（残り0の人にしか配らない仕様）。毎月のきっかけが来ない構造
- Instagram の配信期間はDBにも過去レポートにも無い。「8/17〜」はユーザーの記憶で、要確定

## ③ A群が残高0のときに送ったメッセージ

本文はDBに残っていない。残高0の分岐（`RepController.php:492` 付近）で課金メニューを返して終わるため。回数と日数は、課金メニューの送信時刻から推定した（占い完了直後の自動メニューは除外）。

- 残高0で話しかけた人: 57人中38人、のべ178回（6/28以降は32人・104回）。19人は一度も話しかけていない
- 1人あたり: 0回19人 / 1回14人 / 2〜3回13人 / 4〜9回6人 / 10回以上5人
- 10回以上: u51 35回/21日、u245 29回/11日、u37 14回/13日、u392 13回/10日、u172 12回/11日。話したいのに買わない層で、「価格か主義か」を聞く価値が一番ある
- 時間帯は18〜22時が最多（68回）。課金が起きる22〜3時（24回）とずれる
- 「残り回数」ボタンを押した場合もメニューが送られるため、回数には発話でない操作も混ざる
- 本文を残す → [line_f#64](https://github.com/emomie/line_f/issues/64)

## ④ 止める条件の週次監視

`node scripts/weekly_watch.mjs`（SQLは `queries/weekly_heavy_new_users.sql`）。直近12週で、新規（登録30日以内）の1日10回超は **0人**。1日10回超はu59のみ（8/13に18回、9/2に12回）。

止める条件そのものの見直し案（**運用しながら決める**。9/28時点で未確定）:

| 条件 | 今の値 | 問題 | 見直し案 |
| --- | --- | --- | --- |
| 1日10回超が新規の1%超 | 0人 | 分母30人前後で実質「1人出たら止める」。59型は数ヶ月かけて増える（2月11回→7月60回）ので、登録30日以内では捕まらない | 対象をu59以外の全員に広げ、先行指標（1日6回以上の日、月の回数が前月の2倍）を足す |
| ブロック率30%超 | 累計50.7% | 累計ではすでに超えていて、施策の良し悪しが見えない。DBに記録が無い | 「新規登録から30日以内のブロック率」にする → [line_f#65](https://github.com/emomie/line_f/issues/65) |
| 返金・苦情が月3件以上 | 課金トラブル0件 | 失敗時は返金ではなく補填チケット。補填は7月5・8月7・9月2件で、本番ユーザー分は全部u59 | 課金トラブル（月1件で止める）と補填（u59以外で月3件）を分ける |
| 粗利が単価の20%割れ | 64% | LLM費が10倍にならないと割れない | 「登録1人の単価が2週間平均¥1,000超」に置き換える案 |
